# Security policy

AsanaMind is an evolving prototype and is not currently advertised as production-ready. Please do not include passwords, API keys, database URLs, personal data, or session tokens in reports.

## Reporting

Report suspected vulnerabilities privately to the repository owner through GitHub’s private vulnerability reporting or another private owner-approved channel. Include affected revision, reproduction steps, impact, and a suggested mitigation. Do not open a public issue for an undisclosed vulnerability.

## Deployment baseline

Use HTTPS, a strong secret key, secure cookies, least-privilege MongoDB credentials, dependency updates, rate limiting, backups, and credential rotation. Review authentication, admin authorization, input validation, and retention of account/progress data before production use.
